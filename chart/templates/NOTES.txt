Alquimia chart deployed in namespace {{ include "alquimia.namespace" . }}.
The chart does not manage the namespace. It must exist beforehand (helm --create-namespace).

Secrets: backend={{ .Values.secrets.backend | default "sealed" }}.
{{- if eq (.Values.secrets.backend | default "sealed") "sealed" }}
Helm does not create plaintext Secrets. Generate values-sealed.yaml:

  kubeseal --fetch-cert --controller-namespace sealed-secrets --controller-name sealed-secrets > sealed-cert.pem
  ./chart/scripts/seal-secrets.sh sealed-cert.pem

The Sealed Secrets controller must exist in the cluster.
Do not seal alquimia-vault or vault-keys: vault-unsealer writes them.
{{- end }}

{{- if .Values.vault.enabled }}
Vault is installed by this chart (StatefulSet `vault`).
{{- if .Values.vault.autoUnseal }}
The `vault-unsealer` Deployment runs init + unseal in a loop and stores
the keys and the root token in the secret {{ .Values.vault.keysSecret }}.
If that secret is lost and the Vault PVC remains, there is no way to unseal.
{{- if .Values.runtime.zeroTrust.enabled }}
The runtime reaches Vault with Kubernetes auth. It does not use the `alquimia-vault` Secret.
{{- else }}
Without Zero Trust the runtime reads `VAULT_TOKEN` from the `alquimia-vault` Secret.
{{- end }}
